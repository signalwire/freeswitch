## Directory Responsibilities

| Path | Responsibility | Notes |
|------|----------------|-------|
| `src/` | Core library and `freeswitch` binary | `switch_*.c` (~71 files) plus `switch.c` (`main`), `fs_encode.c`, `fs_tts.c`. Public headers in `src/include/`. |
| `src/mod/` | Loadable modules, grouped by role | Built from `modules.conf` (copied from `build/modules.conf.in`). See table below. |
| `src/include/` | Public C API (`switch.h` and `switch_*.h`) | Module authors include `switch.h`. ~54 headers. |
| `libs/` | Bundled third-party and first-party libraries | APR, SRTP, VPX, ESL (`fs_cli`), xmlrpc-c, NAT helpers. Prefer in-tree copies unless `--with-system-*` / `SYSTEM_APR`. |
| `conf/` | XML configuration profiles | Root `conf/freeswitch.xml` includes `vanilla/freeswitch.xml`. Profiles: `vanilla` (default PBX), `sbc`, `minimal`, `curl`, `insideout`, `softphone`, `testing`. The Users Manual writes paths relative to the **configuration root** (the directory that contains `freeswitch.xml`). |
| `build/` | Autotools helpers, `modules.conf.in`, sounds version files | Not a CMake `build/` output dir. Do not treat as generated. |
| `tests/unit/` | Core unit tests against `libfreeswitch` | Must use `src/include/test/switch_test.h` (`tests/unit/README`). Per-test XML fixtures in `conf_*` subdirs. |
| `libs/esl/` | Event Socket Library and `fs_cli` | Out-of-process control; language bindings under `libs/esl/{perl,python3,lua,ruby,php}`. |
| `debian/`, `scripts/packaging/`, `yum/` | Linux packaging | Debian/Ubuntu packages, FSGET/FSDEB helpers, RPM repo files. |
| `docker/` | Official images and example Dockerfiles | Host networking expected; see `docker/README.md`. |
| `w32/`, `Freeswitch.2017.sln` | Windows Visual Studio build | Console, Library, Setup. |
| `.github/workflows/` | CI | `ci.yml` on `master` / `v1.10` / `v1.11`; also macOS, Windows, tarball, scan-build, unit-test. |
| `scripts/` | Dev, CI, packaging, and example scripts | `scripts/ci/` used by `bootstrap.sh`. |
| `docs/` | Doxygen, Unix man pages, legal copies | `docs/man` is **not** this PKB. |
| `man/` | This Project Knowledge Base (Sphinx) | Bilingual English / `zh_CN`. |
| `htdocs/` | Bundled HTTP/portal assets | Served when XML/HTTP modules are enabled. |
| `fscomm/`, `clients/` | Optional GUI / Flex clients | Not required to run the switch. |
| `support-d/` | Maintainer gdb helpers and keys | Operator debugging, not runtime. |
| `dtd/`, `fonts/`, `images/` | XML DTD, fonts, static images | Supporting assets. |

## Organization Rules

- **Naming**: Core files are `switch_<area>.c` / `switch_<area>.h`. Modules are `mod_<name>` under a category directory. Config files are XML named `<feature>.conf.xml` under `autoload_configs/`.
- **Layering**: `src/switch.c` → core (`switch_core_*`, RTP, IVR, XML) → loadable modules. Modules call into `src/include/`; they must not become a second core. Bundled libs stay in `libs/` and are linked by the core or by specific modules.
- **Module boundaries**: Category folders are the ownership boundary (endpoint vs application vs codec). Enable/disable is `modules.conf`, not `#ifdef` sprawl in the core. Out-of-tree modules can be cloned via `modules.conf` git-source lines (`src/mod/Makefile.am`).
- **Config vs code**: Runtime behavior is XML under `conf/<profile>/`, not compiled constants. The preprocessor (`X-PRE-PROCESS` / `#include`) flattens to `freeswitch.xml.fsxml` at start.
- **Scripts and tooling**: packaging in `scripts/packaging/` and `debian/`; CI glue in `scripts/ci/` and `.github/`; maintainer gdb in `support-d/gdb/`.
- **Tests**: core unit tests in `tests/unit/` (libfreeswitch only). Some modules carry their own `test/` trees (for example Sofia SIPp scenarios under `src/mod/endpoints/mod_sofia/test/`).
- **Build systems**: Autotools is the supported Unix path. `src/CMakeLists.txt` exists but is historical (CMake 2.6 comment). Windows uses the `.sln` / `w32/` project files.
